Overview

A lightweight, plug-and-play utility that quickly tells you which expected classes (Controller & Model) actually exist for any given module in a CodeIgniter MVC project. Drop it in, log in once, and start validating your modules in seconds.

Getting Started

1. Install

Copy the entire directory into your project root. No composer installs, no environment tweaks—just drag, drop, done.

2. Grab the Access Key

Look for the text file whose name is obnoxiously long (you literally can’t miss it). Open it and copy the key.

3. Log In

Visit /module-tester, paste the key, hit Enter. The key is stored in sessionStorage for the tab, so refresh-safe but not forever.

UI Flow

  1. Login screen – one input, one button.
  2. Module Tester UI – a single input for the module name (case-sensitive).
  3. Results panel – instant feedback plus optional “Test File” buttons.

REST API Reference

POST /test_ops.php

Body (JSON):

Success HTTP code is 200. Anything else means something went sideways.

Primary Response Object

maname
string – the exact module name you sent
datapassed
bool – true if the module parameter was non-empty
hascontroller
bool – true if Controllers/{Module}.php exists
hasmodel
bool – true if Models/{Module}Model.php exists

Testing a File

When either the Controller or the Model is detected, a green button labeled Test Controller code or Test Model code appears. Clicking it fires a fetch() request to the file itself and returns:

status
200 = OK, 500 = server error, anything else = “you fucked up”
status_text
"OK" or an error message
ajax_text
Should be empty if your PHP is clean
color
CSS class: green or red

Quick Start (TL;DR)

  1. Copy folder (testsite) → project root.
  2. Open the ridiculously-long-named text file → copy key.
  3. Browse to /module-tester, enter key.
  4. Type module name → hit Enter.
  5. Green = good, red = bad, fix accordingly.
